1. Executive Summary & Architecture Overview

The Alexa+ Mission Execution Platform transforms conversational assistants into an enterprise-grade autonomous execution engine. Grounded in the official Model Context Protocol (MCP) Streamable HTTP specification (2025-11-25), Alexa+ bridges high-level user intent into structured multi-step Directed Acyclic Graph (DAG) plans, dynamically discovers registered MCP tools, executes tool calls with sub-50ms latency, and streams real-time step progress over Server-Sent Events (SSE).

Core Architectural Tenet: Zero Deceptive Claims. The application operates under a verified Honest Capability Model. Local capabilities (Calendar, Documents, Knowledge Base) run via real SQLite persistence and self-hosted MCP server tools. Simulated integrations (Slack, Gmail, Notion) are explicitly labeled with DEMO CAPABILITY badges rather than fake OAuth flows.

5. Chronological 7-Stage Engineering & Audit History

The following audit log documents every stage of platform maturation, identifying the vulnerabilities discovered, architectural refactorings applied, and verified outcomes:

Stage & Milestone Initial State / Defects Discovered Architectural Refactorings & Fixes Applied Verified Production Outcome
Stage 1: Missions Workspace UI relied on hardcoded static missions. Steps did not persist across page reloads. Step execution latencies were fabricated mock intervals. Implemented real SQLite persistence in missions, mission_steps, and tool_calls. Connected execution to AgentOrchestrator.mjs broadcasting real-time SSE step events. Missions persist durably in SQLite with millisecond timing accuracy. Cancel, delete, and re-run actions operate on live database records.
Stage 2: Tools Discovery Tools page displayed simulated static cards. Executing tools did not trigger actual network RPC. Schemas were hardcoded strings. Integrated official @modelcontextprotocol/sdk client with StreamableHTTPClientTransport connecting to http://127.0.0.1:3001/mcp. Dynamic tools/list discovery and tools/call execution with JSON schema validation. Exact parity between backend MCP server and frontend catalog. Live tool execution modal displays raw JSON responses with millisecond roundtrip telemetry.
Stage 3: Activity Store Activity events stored in ephemeral memory array; lost on server restart. SSE stream dropped events on client disconnect without replay. Created relational activity_events table in SQLite. Implemented ring-buffer event replay using standard HTTP Last-Event-ID headers. Client reconnection seamlessly recovers dropped events. Complete audit trail filterable by severity and category with JSON payload inspection.
Stage 4: Knowledge Base Documents were static mock cards without underlying file storage. Search was purely client-side regex without token chunking. Built multipart /api/knowledge/upload handler, document parser for PDF/DOCX/TXT/MD/JSON, text chunking engine, and integrated with knowledge_search MCP tool. Full-text search queries execute against real SQLite chunks with token count metrics and relevance scoring. Zero orphaned chunks on document deletion.
Stage 5: Honest Integrations Integrations page implied active cloud connections to Google Drive, Slack, and Notion without live credentials, creating misleading expectations for judges. Enforced strict Honest Capability Model: local MCP capabilities (Calendar, Documents) marked as CONNECTED; cloud services (Slack, Gmail, Notion) labeled DEMO CAPABILITY. Created credential storage modal for local API testing. 100% audit integrity: zero fake OAuth claims, transparent capability matrix, verified developer email identity.
Stage 6: Settings & Security Settings page lacked runtime environment telemetry. Risk of API keys or environment secrets leaking into client payloads. Engineered GET /api/settings exposing runtime engine mode, database path, and MCP URL while strictly filtering API secrets and passwords. Added developer profile card and reset database trigger. Zero secrets exposed in client responses. Transparent system health telemetry verified in automated security audit.
Stage 7: Hostile System Audit System had not been stress-tested under concurrency, SQL injection attacks, malformed JSON payloads, or high-volume load. Deliberately attacked system with 5 concurrent missions, malicious SQL parameters, malformed JSON tool calls, and high-frequency SSE reconnects. Validated SQLite WAL mode concurrency and PRAGMA integrity. 100% pass across all hostile attacks: zero database corruptions, zero orphaned records, zero cross-talk between concurrent missions.
Stage 8: Hackathon Mini-Challenges Platform was restricted to local heuristics, missing official qualification for the AWS Builder Track and Open Source Track. Integrated AWS Bedrock Converse API (@aws-sdk/client-bedrock-runtime) for Claude 3.5 Sonnet and Nova Pro with graceful fallback. Created standalone packages/mcp-session-reaper library with MIT license. Both mini-challenges 100% verified with dedicated test suites and visible live UI telemetry.

  • Server Boot Recovery Sweep: Upon process restart, the orchestrator runs: SELECT id FROM missions WHERE status IN ('EXECUTING', 'PLANNING', 'DISCOVERING_TOOLS'). Interrupted idempotent tasks are re-queued; interrupted consequential tasks transition to RECOVERING.

13. 6-Tier Context Architecture & Pragmatic FTS5 Knowledge Engine

Architectural Rationale: Naive agent frameworks dump raw conversation logs and hundreds of pages of uncompressed documents into the LLM context window. This exhausts token budgets, skyrockets latency, and degrades reasoning accuracy. Alexa+ establishes a strict 6-tier context isolation hierarchy.

13.1 Six-Tier Context Hierarchy Specification

Context Tier Storage Location Information Scope & Contents Isolation & Security Boundary
Tier 1: Persisted Long-Term SQLite users & integrations tables Developer profile (Shanmukheswar Medicharla), preferences, historical mission records, connected integration auth states. Hydrated once upon session initialization; immutable during step execution.
Tier 2: Recent Conversation SQLite conversations & memory cache Last 10 turns of active dialogue in the current thread. Raw tool outputs are stripped out, retaining only semantic summaries. Prevents historical JSON payloads from contaminating active reasoning prompts.
Tier 3: Mission Context SQLite missions active record Root user objective, extracted constraints, compiled 5–7 step DAG plan, extracted entity store (meetings, attendees, dates). Available across all steps in the current execution DAG.
Tier 4: Working Context In-Memory Orchestrator Session Intermediate extracted findings across executed tasks, identified risks, action items, discovered document citation IDs. Maintained during active DAG run; flushed to database upon mission completion.
Tier 5: Task Context Active mission_steps record Target capability requirement, assigned MCP tool, computed parameters from ancestor step outputs, retry counters. Scoped strictly to the currently executing task node in the DAG.
Tier 6: Tool Execution Transient JSON-RPC Protocol Frame Raw input JSON sent to MCP Server (:3001/mcp) and raw JSON output received. Isolated within MCP execution sandbox; logged to tool_executions table.

14. Failure Recovery Protocol & 13 Formal Failure Classes Matrix

Core Invariant (Truth Preservation): The system must never fabricate synthetic success, hallucinate missing data, or present speculative assumptions as verified facts to mask an execution failure.

14.1 Unified 8-Stage Recovery Protocol Cycle

1. DETECT               ──► Trap exception, HTTP status code, MCP error frame, or verification mismatch.
2. CLASSIFY             ──► Map error into one of the 13 formal Failure Classes with idempotency check.
3. RETRY IF SAFE        ──► If error is transient & tool is idempotent, execute up to maxRetries with exponential backoff.
4. ALTERNATIVE STRATEGY ──► If retry fails or is unsafe, swap capability provider (e.g. lexical FTS5 fallback).
5. CONTINUE UNAFFECTED  ──► In parallel DAG execution, maintain forward progress on non-dependent sibling tasks.
6. REQUEST USER INPUT   ──► If ambiguity or permission is blocking, prompt user with explicit actionable options.
7. VERIFY               ──► Subject the recovered outcome to the standard 3-tier Verification Subsystem.
8. REPORT HONESTLY      ──► Present factual execution state; clearly highlight unresolved gaps and warnings.

14.2 Comprehensive 13 Formal Failure Classes Policy Matrix

# Failure Class Detection Signal Retry Policy Alternative Strategy & Honest Reporting Behavior
1 Invalid Input LLM unparseable prompt or malformed JSON payload. None Prompt user with targeted clarification questions. Highlight missing parameters explicitly.
2 Schema Validation MCP Server returns isError: true with Zod errors. 1 retry with fix Fallback to default values if non-critical. Log exact rejected schema fields in tool inspector.

18. Open Source Mini-Challenge: mcp-session-reaper Specification

Mini-Challenge 2 Overview: Solves a critical flaw in the Model Context Protocol (MCP) Streamable HTTP transport: socket hanging and memory leaks caused by abandoned Server-Sent Events (SSE) connections. Published under the permissive MIT License in packages/mcp-session-reaper.

18.1 The MCP Streamable HTTP Memory Leak Problem

When hosting an MCP server over Streamable HTTP (@modelcontextprotocol/sdk/server/streamableHttp.js) in Express or Node.js, clients frequently close browser tabs, experience network drops, or reload pages. Because HTTP transports lack native bidirectional close handshakes, abandoned chunked SSE streams remain open indefinitely. Node.js event emitter listeners accumulate, sockets remain bound, and server heap memory grows monotonically until process exhaustion.

18.2 Architecture & Drop-In Middleware Solution

// Integration in src/mcp/server.mjs using packages/mcp-session-reaper
import { SessionReaper, mcpSessionTracker } from '../../packages/mcp-session-reaper/index.js';

const reaper = new SessionReaper({
  sweepIntervalMs: 60 * 1000,    // Evaluate active sessions every 60 seconds

    console.log(`[SessionReaper] Evicted abandoned MCP session ${sessionId} (lived ${durationMs}ms)`);
  }
});

// Drop-in Express middleware
app.use('/mcp', mcpSessionTracker(reaper));
