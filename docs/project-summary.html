1. Executive Summary & Positioning

This project is an Alexa+-inspired autonomous agentic assistant platform built around the official Model Context Protocol (MCP) Streamable HTTP specification (spec 2025-11-25+). Rather than simulating tool execution through static chat prompts, the platform connects an agent orchestrator to an independent self-hosted MCP server (:3001/mcp) over HTTP with dynamic capability discovery and persistent SQLite state tracking.

Detailed Inspection Cards for Priority Polish & Non-Working Elements

1. Natural Language Microphone / Speech-to-Text Button ⚠️ PARTIAL / BROWSER-DEPENDENT

Location: Home Page — Natural Language Composer (NewConversationPage.tsx)

Why It's in the UI: Emulates native Alexa hands-free voice prompting, allowing users to speak their goals.

How It Works Under the Hood: Uses the native browser webkitSpeechRecognition API. When clicked, it requests microphone permissions, listens to user voice input, and transcribes text directly into the textarea.

Why It Might Fail / Operational Reality: Fails on Firefox, Safari, or Chrome instances where microphone permissions are denied or running in non-secure HTTP contexts.

Step-by-Step Fix Blueprint for Next Session:

  • In src/web/pages/NewConversationPage.tsx, wrap the click handler with a fallback to the standard navigator.mediaDevices.getUserMedia + MediaRecorder API.
  • Record the audio blob and send via multipart/form-data to POST /api/speech/transcribe, processed by local Whisper or Bedrock audio transcription.
2. Delete Mission Action (Three-Dots Menu) ❌ PENDING POLISH (SAFETY RISK)

Location: Missions Workspace — Header Dropdown (MissionWorkspacePage.tsx)

Why It's in the UI: Allows users to prune stale, completed, or failed missions from the database.

How It Works Under the Hood: Immediately issues DELETE /api/missions/:id to the backend, cascading deletes across SQLite tables (missions, mission_steps, tool_calls) and switching the UI to the latest remaining mission.

Why It Needs Polish: There is currently NO confirmation dialog. A user or judge who accidentally clicks "Delete Mission" loses the entire mission history without an "Are you sure?" prompt.

Step-by-Step Fix Blueprint for Next Session:

  • In MissionWorkspacePage.tsx, add a state isDeleteConfirmOpen.
  • When "Delete Mission" is clicked, open a modal with "Confirm Deletion" and "Cancel" buttons before issuing the API delete request.
3. Notification Bell Dynamic Unread Counter ❌ PENDING POLISH (VISUAL FEEDBACK)

Location: Global Header — Top Right (Header.tsx)

Why It's in the UI: Alerts the user when asynchronous missions complete or when tool errors occur in background execution.

How It Works Under the Hood: Clicking the bell icon navigates to /activity. However, the bell icon currently has no dynamic red badge counter showing unread notifications.

Why It Needs Polish: The user has no visual clue that a background mission has finished unless they manually check the Activity page.

Step-by-Step Fix Blueprint for Next Session:

  • In src/web/state/, add an unreadCount state initialized from GET /api/activity?unread=true.
  • Subscribe to the global SSE stream in Header.tsx; increment unreadCount on mission.completed and render a small red pill <span className="bg-red-500 rounded-full">{unreadCount}</span>.
  • Reset counter when user visits /activity.
4. Third-Party Live Cloud OAuth Sync (Slack, Gmail, Google Cloud) ⚠️ ARCHITECTED FOR NEXT PHASE

Location: Integrations Matrix (IntegrationsPage.tsx)

Why It's in the UI: Demonstrates real-world enterprise capability connectors for Google Workspace, Slack, and Notion.
